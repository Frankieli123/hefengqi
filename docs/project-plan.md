# HEFENGQI 官网项目计划

更新日期：2026-09-07

## 1. 项目目标

建设面向通信与能源设备集成商、采购团队的中英俄三语 B2B 官网，并提供自主管理内容、产品资料复核、询盘处理、AI 辅助资料采集和自有服务器部署能力。

网站不是商城或 SaaS 后台。公开端不展示价格、库存，不提供结算、会员、CRM 或公共文档下载中心。

## 2. 已确定范围

- 语言与路径：中文 `/zh`、英文 `/en`、俄文 `/ru`。
- 公开模块：首页、产品中心、三级以内分类、产品详情、最多三个产品对比、解决方案、行业、案例、新闻、关于、联系、搜索、隐私和条款。
- 内容后台：产品、品牌、分类、参数、媒体、方案与文章、询盘、采集来源、任务和自动化设置。
- 权限：`ADMIN` 和 `EDITOR`，后台账号强制启用 TOTP 两步验证。
- 数据原则：人工录入和本地授权资料优先；锁定值不可被网页来源或 AI 覆盖；未知事实不得推测。
- 技术栈：Next.js 16、TypeScript、Tailwind CSS v4、Prisma、PostgreSQL。
- 部署：自有中国大陆 Linux 服务器、Docker Compose、腾讯 EdgeOne、Caddy，仅开放源站 HTTPS 8443。
- 配套服务：Worker、ClamAV、Umami、加密 restic 备份和外部 MinIO。

## 3. 系统架构

```text
访客 / 搜索引擎
        |
        v
腾讯 EdgeOne（DNS、CDN、WAF、缓存）
        |
        | HTTPS 8443 + 私有回源 Host + 共享请求头
        v
Caddy（TLS、源站鉴权、公开 Host 透传）
        |
        +--> Next.js Web --> PostgreSQL
        |         |              ^
        |         +--> ClamAV    |
        |                        |
        +--> Umami          Worker（邮件、采集、AI、保留策略）
                               |
                               +--> OpenAI 兼容接口 / Resend

PostgreSQL + 媒体卷 --> restic 加密备份 --> 外部 MinIO
```

Web 与 Worker 使用两个独立镜像标签。数据库迁移、种子数据和首个管理员初始化均使用 Worker 镜像执行。

## 4. 内容和发布流程

### 产品

1. 人工建立已核实的品牌、分类和参数定义。
2. 创建产品草稿并录入三语定义、用途、优势、SEO 字段和技术参数。
3. 产品图片上传时校验类型、魔数与图像可解码性，选择关联图片作为主图即可；产品文档及通用媒体库素材继续执行安全检查。
4. 发布门禁检查品牌状态与权利、分类状态、三语完整度、必填参数及是否已选择产品主图，不要求主图扫描或授权状态。
5. 已发布内容发生人工修改时自动回到草稿，并保存修订快照。

### 网页和 AI 辅助资料

1. 只采集允许的公开 HTTPS 静态页面，并执行 robots.txt、速率限制、DNS 和 SSRF 检查。
2. AI 只抽取带原文证据的候选事实，不直接创造产品或公司事实。
3. 候选事实只填充安全可写字段，不覆盖锁定值或优先级更高的资料。
4. 参数写入、产品状态、导入记录和审计日志在同一数据库事务中完成。
5. 自动发布必须同时满足全局开关、来源开关和全部发布门禁。

## 5. SEO 和 GEO 验收标准

- 每个可索引页面具有独立标题、描述、唯一 H1、canonical、Open Graph 和 hreflang。
- 产品页明确回答“是什么、解决什么问题、适合谁、核心优势、技术参数”。
- 重要内容提供可验证的结构化数据，包括 Organization、WebSite、Product、FAQ、Breadcrumb、Article、CollectionPage 和 ItemList。
- sitemap 包含静态页、分类、产品和编辑内容；图片使用独立图片站点地图。
- 提供运行时生成的 `robots.txt` 和 `llms.txt`，正式域名不会在镜像构建时写死。
- 三种语言的实体名称、型号、数字和单位保持一致，不用自动翻译替换品牌或型号。

## 6. 安全和运维验收标准

- 源站公网只允许 EdgeOne 官方回源 IP 访问 TCP 8443。
- Caddy 校验共享回源请求头，并把公开 `Host`/`X-Forwarded-Host` 传给 Next.js。
- 后台和 API 不被 CDN 缓存，认证操作经过权限、2FA 和服务端输入校验。
- Server Actions 使用稳定的构建期加密密钥，CI 通过 BuildKit secret 注入。
- 产品图片必须通过类型、魔数和图像解码校验，但发布不要求 ClamAV 扫描或授权确认；产品文档与 Hero 等通用媒体仍执行扫描和授权门禁。
- PostgreSQL、媒体和私有上传定期加密异地备份；上线前完成隔离恢复演练。
- 部署使用不可变 Git SHA 镜像，失败时恢复上一镜像标签。

## 8. 需要业主确认或提供

### 上线阻塞项

1. 公司与品牌：正式中文、英文、俄文公司名称，品牌显示名称和 Logo 源文件。
2. 域名：公开主域名，以及不公开解析给访客的源站域名。
3. 联系资料：经核实的地址、销售邮箱、电话、WhatsApp 或其他对外渠道。
4. 合规资料：ICP备案展示文本、隐私政策和条款中的法律主体信息。
5. 产品内容：已核实的品牌/型号/分类/参数、授权图片、允许公开的案例与资质材料。
6. 服务器：Linux 发行版、CPU、内存、磁盘、机房区域和现有防火墙方式。

### 服务与账号选择

1. GitHub 仓库及 GHCR 镜像归属组织。
2. 腾讯 DNS 和 EdgeOne 站点归属及回源配置负责人。
3. Resend 发信域名和销售收件邮箱。
4. Cloudflare Turnstile 站点。
5. OpenAI 兼容服务的地址和模型名称。
6. 外部 MinIO 的区域、容量和保留周期。
7. Umami 是否使用当前自建方案，以及数据保留周期。

密钥、密码和令牌不应通过聊天发送。它们应直接写入服务器权限为 `0600` 的 `.env.production`，或 GitHub `production` Environment Secrets。
