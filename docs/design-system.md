# HEFENGQI 官网设计系统

更新日期：2026-09-12
适用范围：公开官网 `/zh`、`/en`、`/ru`、`/fr`、`/de`、`/es`、`/ar`。后台沿用同一色彩、圆角和可访问性基线，但信息密度可以更高。

## 1. 设计原则

- 学习高端科技官网的克制、清晰和大留白节奏，不复制其他品牌的 Logo、图片、文案、专属图形或代码。
- 用内容、留白、背景色和细边框建立层级；普通状态不使用重投影。
- 白色、石墨黑、冷灰为主，`#C7000B` 仅用于行动、当前状态、短横杠和少量重点。
- 所有互动必须可感知，但不使用滚动劫持、无意义视差或大规模飞入动画。
- 保留键盘焦点；“去掉红框”只针对鼠标点击残留效果，不能移除键盘用户的可见焦点。

## 2. 设计令牌

当前令牌的实现源是 [`src/app/globals.css`](../src/app/globals.css)。新页面和新组件优先复用这些令牌，不能随意写入接近但不同的颜色或圆角值。

### 2.1 色彩

| 角色 | 值 | 用途 |
| --- | --- | --- |
| 页面底色 | `#FFFFFF` | 默认页面和内容卡片 |
| 分区/卡片底色 | `#F7F7F7` | 浅灰内容分区、普通卡片背景 |
| 次级底色 | `#F1F3F5` | 次要控件、图片占位区 |
| 主文字 | `#1F1F1F` | 标题和主要正文 |
| 次级文字 | `#666666` | 摘要、说明、元数据 |
| 品牌红 | `#C7000B` | 主行动、当前状态、进度、标题短横杠 |
| 品牌红 Hover | `#A80009` | 主按钮 Hover/按下反馈 |
| 深色分区 | `#141414` | 深色 Hero、强调区或页脚 |
| 边框 | `#D8D8D8` | 常规输入框和内容边界 |

红色不是普通文字色。除当前状态、可操作提示和重要行动外，正文与普通标题保持石墨黑。

### 2.2 圆角

| 值 | 语义 | 使用场景 |
| --- | --- | --- |
| `2px` | 极小元素 | 细进度、微型装饰 |
| `4px` | 微圆角 | 标签、徽章、Logo 小图形、内嵌元素 |
| `8px` | 标准 | 按钮、输入框、产品目录卡片、标准容器 |
| `12px` | 大内容块 | 首页产品系列卡片、普通大卡片 |
| `16px` | 浮层/轮播 | Hero 控制面板、对话框、大模块 |
| `9999px` / `50%` | 胶囊/圆形 | 开关、圆形图标按钮、状态点 |

禁止把所有元素做成大圆角。一个页面中的卡片应按内容层级选择 `8px` 或 `12px`，不混用任意值。

### 2.3 阴影和边框

- 普通卡片：无投影；可使用 `1px` 的低对比边框。
- 可悬停媒体/产品卡片：仅 Hover 使用 `0 4px 20px rgb(0 0 0 / 8%)`，同时上移 `2px`。
- 弹窗、下拉菜单和侧栏可以使用轻投影，以明确脱离页面层级。
- 不使用明显的厚阴影、彩色阴影或拟物浮雕。

## 3. 字体与排版

### 3.1 字体栈

```css
"Manrope Variable", "HarmonyOS Sans SC", "PingFang SC",
"Microsoft YaHei", "Noto Sans SC", "Noto Sans Variable", Arial, sans-serif
```

- 英文、数字和俄文：优先 Manrope。
- 中文：优先设备中的 HarmonyOS Sans SC 或 PingFang；项目随站点加载 Noto Sans SC 作为可靠回退。
- 不能只依赖设备字体，也不能在单个页面临时指定其他展示字体。
- 如未来取得可网页分发的 HarmonyOS Sans SC 授权，应将其作为项目字体文件加载，再统一更新本节与全局字体栈。

### 3.2 字号层级

| 层级 | 字号与行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Hero H1 | `32–48px` / `1.25` | `600` | 首页首屏唯一 H1、页级核心视觉标题 |
| 页面 H1 | `30px` 移动起、桌面 `48px` | `600` | 产品、解决方案、行业等页面头图 |
| 模块 H2 | `28–32px` / `1.35` | `600` | 普通内容分区标题，包括“产品系列” |
| 卡片 H3 | `18–20px` / `1.4` | `600` | 产品系列、内容卡片标题 |
| 导航 | `16px` / `1` | `400`，当前项 `500` | 主导航 |
| 正文 | `16px` / `1.5–1.75` | `400` | 摘要、说明、正文 |
| 按钮 | `14px` / `20px` | `500` | 默认与大尺寸按钮 |
| 元数据/眉题 | `12px` | `500–600` | 时间、标签、顶部信息栏、眉题 |

- 标题使用 `600` 为主，不使用 `700` 作为常规页面标题。
- 标题可使用轻微负字距；正文不使用负字距。
- 文案较长时优先调整容器宽度、换行和行高，不通过缩小到低于本规范的字号解决。

## 4. 布局与间距

- 默认内容容器：最大 `78rem`（1248px），移动端左右安全边距 `16px`。
- 产品目录容器：最大 `88rem`（1408px），允许承载筛选栏与三列产品卡片。
- Header 内容容器：最大 `82.5rem`（1320px）。
- 常规分区上下间距：`clamp(64px, 8vw, 112px)`。
- 使用 4px 的倍数建立间距；优先使用 `8 / 12 / 16 / 24 / 32 / 48 / 64px`。
- 页面通过白色与浅灰分区交替形成层级，避免给每个区块增加边框或阴影。

## 5. 核心组件

### 5.1 按钮

- 默认高度 `40px`，大按钮 `44px`，普通矩形按钮使用 `8px` 圆角。
- 主按钮：品牌红底、白字；Hover 使用 `#A80009` 或轻微透明度变化；按下可使用 `opacity: .85`。
- 次按钮：白底细边框；Hover 不铺大面积灰底，只可改变边框、文字或箭头。
- 搜索、开关、图标工具可使用胶囊或圆形；不得把业务 CTA 做成胶囊。
- “查看详情”等文字行动在 Hover 时箭头右移 `4px`，标题可在 `200ms` 内转为品牌红。

### 5.2 卡片

- 产品目录卡片：`8px` 圆角，轻边框，无静态阴影。
- 首页产品系列卡片：`12px` 圆角，图片在上、内容在下；桌面三列，平板两列，移动一列。
- 图片使用 `object-fit: cover`；Hover 仅缩放到 `1.04`，时长 `400ms`。
- 卡片 Hover 上移最多 `2px`，不能出现大幅浮起或明显灰色底板。

### 5.3 输入与搜索

- 默认输入框：`8px` 圆角、`1px` 边框、最小可触控高度 `32px`；搜索输入可为 `40px`。
- Header 搜索桌面端从放大镜位置横向展开，导航文字缩小隐藏但 Logo 保留。
- 移动端搜索从右侧进入全屏面板，并展示热门链接。
- 输入聚焦使用边框变化与可见焦点，不使用强烈发光阴影。

### 5.4 标题下品牌红线

仅用于居中的营销型模块标题，例如首页“产品系列”。规则参考华为官网“推荐信息”的实际计算样式：

```css
position: relative;
padding-bottom: 8px;

&::after {
  content: "";
  position: absolute;
  inset-inline-start: 50%;
  bottom: 0;
  width: 30%;
  height: 2px;
  background: #C7000B;
  transform: translateX(-50%);
}
```

- 不使用固定 `80px × 4px` 的粗横杠。
- 不在产品分类侧栏、普通表单标题或面包屑下重复使用此装饰。
- 内容标题本身是重点时，短横杠可省略。

### 5.5 Header 与导航

- 顶部信息栏与主导航作为一个整体随页面向下滚动收起；不缩放 Header 高度造成布局跳动。
- 主导航在容器中居中，Logo 固定在左，行动与语言/搜索在右。
- 导航 Hover 和当前页使用 `2px` 品牌红下划线展开反馈，时长 `300ms`。
- 右侧 Hero 下一张箭头可在 Hover 时显示完整浅灰色点击区；这是明确的轮播控制反馈，不推广到普通按钮。

### 5.6 解决方案落地页

- 信息层级固定为：黑色栏目标题区、页内导航、方案方法、核心行业场景、品牌方案组合、项目咨询 CTA。
- 栏目标题区与新闻、方案及案例索引页共用同一组件：`page-shell` 内容宽度、`py-16 md:py-24` 垂直留白、左对齐 H1 与 `40×2px` 品牌红短横线。
- 核心行业采用大图卡片和非对称网格建立视觉节奏，图片占主体、文字位于独立白色内容区，不在图片上堆叠长段正文。
- 品牌方案卡片桌面端采用首行三列、次行两列的平衡布局；卡片需同时给出能力范围、站内产品入口和品牌公开资料入口。
- 不复制品牌官网或竞品图片，不引用无法核验的效率、份额、认证及客户成绩；品牌授权和可供应范围必须保留项目复核说明。
- 解决方案详情沿用通用内容详情结构，但必须提供 16:9 场景图；常青方案内容不显示数据库更新时间。
- 公开站只保留一个“解决方案”栏目，使用原行业场景数据与页面结构；历史 `/industries` 地址统一重定向到 `/solutions`，不在导航、页脚或站点地图中重复展示。

### 5.7 分区导航与新闻分类

- 需要同页切换或锚点导航时，栏目标题区下使用 `64px` 高白色分区导航；文字 `14px/500`，当前项以 `2px` 品牌红底线标识，移动端允许横向滚动。
- 新闻分类固定为“行业洞察 / 选购指南 / 教程指南”，中、英、俄使用对应本地化名称。
- 新闻分类来源于后台文章字段，不按标题或关键词在客户端猜测；分类入口集中在“栏目导读”，切换列表不刷新页面，并以 `aria-pressed` 标明当前状态。

### 5.8 新闻动态列表

- 栏目头图与技术支持共用 `EditorialPageHeader`，保留黑底标题；不在标题区下方重复放置分类导航，分类入口集中到右侧“栏目导读”，默认显示全部文章。
- 内容区沿用技术支持的布局节奏与实际 `page-shell` 容器：面包屑后留 `24px`，桌面 `≥1280px` 为弹性主列表与 `272px` 栏目导读，间距 `48px`；较窄屏幕单列，导读放在文章列表下方。
- 黑底栏目头图之后不重复放置栏目介绍，也不设置文章搜索框；面包屑后直接进入“最新文章”列表。
- 文章标题桌面 `20px/600`、移动 `18px/600`，避免每篇文章重复使用模块级大标题。
- 文章列表不用序号和静态投影，以细线分隔；分类与真实发布日期在标题上方，摘要最多两行。移动端标题最多三行，桌面保留完整标题。
- 缩略图统一 `16:10`，桌面宽 `200px`、移动宽 `88px`；无图使用简洁文档图标，不伪造配图。图片、标题和“查看详情”为同一个链接，键盘只需聚焦一次。
- “查看详情”在桌面卡片最右侧垂直居中；移动端放在文案下方右对齐。分类筛选提供结果数量、空状态和清除入口。
- 桌面双栏状态下“栏目导读”使用 `position: sticky; top: 128px`，高度超出视口时允许自身滚动。
- 栏目导读底部使用“需要定制解决方案？”联系模块并链接联系页；内部可滚动但隐藏可见滚动条，避免出现第二条页面滚动轨道。
- 列表 Hover 不铺灰底，仅标题变红、箭头右移 `4px`、图片放大至 `1.04`；遵从鼠标设备门禁与 reduced-motion。
- 使用 `news-feed.module.css` 隔离布局样式，不能影响新闻详情、技术支持或案例页。文章正文不传入列表的客户端数据。

### 5.9 新闻详情

- 详情页使用面包屑、浅灰底顶部左图右文、白底双栏正文、下方相关产品；标题页头的底色与垂直留白跟技术支持详情一致，右侧显示文章分类、摘要、真实作者与发布/更新时间。
- 新闻标题页头与正文使用同一个 `page-shell` 右边界，桌面图文比例约为 `30% / 70%`；长标题使用自然优化换行，通过调整图文比例获得空间，避免为了均衡行宽而过早断行。
- 标题下方摘要与标题共用完整的右侧列宽，不额外设置较短的正文宽度上限。
- 文章封面只在顶部左侧显示一次，保持 `16:9` 和 `8px` 圆角；正文上方不重复图片，没有封面时不生成占位海报。
- 正文直接开始呈现文章内容，不额外显示“正文 / Article / Статья”标题。
- 正文按后台 TipTap JSON 语义进行服务端渲染，允许 H2/H3、粗体、斜体、有序/无序列表、引用、行内代码、代码块、链接和分割线；不得先压平成普通段落，也不得通过 `dangerouslySetInnerHTML` 输出后台内容。
- 后台编辑器允许粘贴常用 Markdown，并在保存前转换为同一套结构化 JSON。历史正文中保留的 `**…**`、反引号、`1.`/`1\.`、`•` 等标记由内容仓库兼容转换，无需在页面组件中为单篇文章添加特例。
- 新闻页面只有页头文章标题使用 H1；正文从 H2 开始，章节下的小标题使用 H3。
- 移动端页头顺序为分类眉题、封面、标题摘要和元信息；桌面端仍为左图右文。
- 正文与相关产品之间不使用额外阴影或分割线，以白底与浅灰区块自然过渡。
- 桌面端正文区为 `272px` 近期资讯与弹性正文两列，间距 `48–64px`。近期资讯使用 `position: sticky; top: 128px`，最大高度不超过可视区并允许自身滚动。
- 移动端和较窄屏幕恢复单列，正文在前、近期资讯在后，不使用 sticky，避免挤压正文阅读宽度。

### 5.10 在线客服浮窗

- 公开站右下角固定在线客服入口，使用品牌红色 `52px`（移动端 `48px`）纯圆形图标按钮；桌面距边缘 `32px`，移动端距边缘 `12px`，不遮挡主要内容和底部操作区。按钮不显示文字，但必须提供本地化 `aria-label`。
- 展开面板宽度约 `384px`，采用石墨黑标题栏、白色内容区和 `16px` 圆角；显示后台配置的真实在线/离线状态。面板高度不得连同入口按钮超出可视区。
- 消息直接进入对话，不设置“产品选型 / 技术支持 / 获取报价”等前置快捷选项。客服消息使用冷灰气泡，访客消息使用品牌红气泡，并在气泡下方标注发送方与时间。
- 输入区固定在面板内容底部，使用 `18px` 圆角、品牌红描边、上方文本区和右下圆形发送按钮；不在输入框上方重复显示“您的问题”等字段标签。`Enter` 发送，`Shift+Enter` 换行。
- 客服在后台“在线客服”收件箱中回复，访客端通过轻量轮询接收回复。邮件保留 `mailto:` 直达行为，不伪装成站内弹窗或复制动作；WhatsApp 使用 `https://wa.me/8617621197907`（号码由后台配置）。
- 会话仅向浏览器保存随机访客令牌，数据库保存 HMAC 摘要；公开 API 做消息长度、状态和频率限制。客服浮窗支持中、英、俄、法、德、西、阿七语，`prefers-reduced-motion` 下取消展开动画。
- 外部通知通过后台可配置的 HTTPS Webhook 推送，事件使用 HMAC-SHA256 签名；详细字段见 `docs/customer-service-webhook.md`。

## 6. 动效与交互

| 场景 | 时长 | 曲线/规则 |
| --- | --- | --- |
| 常规 Hover、导航下划线 | `300ms` | `cubic-bezier(.4, 0, .2, 1)` |
| 标题变色、箭头移动 | `200ms` | 平滑过渡，箭头右移 `4px` |
| 图片卡片缩放 | `400ms` | `ease`，最大 `scale(1.04)` |
| Hero 图片淡入叠化 | `700ms` | 仅当前轮播切换 |
| Hero 图片轻推近 | 每张停留期间 | `scale(1)` 至 `scale(1.025)` |
| Hero 文案切换 | `200ms` 推入 | 旧文案立即移除；当前文案延迟 `200ms`，其余标签延迟 `250ms` |
| 产品共享元素过渡 | `140–360ms` | 只用于产品相关元素 |

- Hero 自动轮播间隔为 `3s`；鼠标悬停、焦点进入、触控手势和页面隐藏时暂停。
- 移动端 Hero 支持左滑下一张、右滑上一张；明显纵向滑动不能触发切换。
- 新增公开站动效应只过渡必要属性，避免无目的的 `transition: all`。
- `prefers-reduced-motion: reduce` 下关闭自动轮播、缩放、位移和滚动显现，内容始终可见且按钮仍可立即切换。

## 7. Hover、焦点与可访问性

- 只在 `(hover: hover) and (pointer: fine)` 设备上启用图片缩放、卡片浮起等鼠标专属反馈。
- 触屏设备不依赖 Hover 才能发现内容或执行操作。
- 所有可点击控件必须可键盘聚焦；焦点轮廓至少 `2px`，不能被 `outline: none` 替代而没有等效样式。
- 自动轮播不强制读屏播报；控件有明确文字标签和 `aria-current` 状态。
- 最小触控尺寸为 `44px × 44px`；轮播箭头和移动端主控件必须满足。
- 图片均需要与内容语言一致的 `alt` 文本；装饰图片使用空替代文本。

## 8. 响应式规则

| 区间 | 规则 |
| --- | --- |
| `< 768px` | 单列优先；Hero 文案在上、图片在下；搜索使用右侧全屏面板；Hero 支持滑动 |
| `768–1023px` | 两列产品系列卡片；桌面 Header 搜索展开逻辑开始生效 |
| `≥ 1024px` | 首页产品系列三列；正文保持最大阅读宽度 |
| `≥ 1280px` | 产品目录三列 |

在 `375px`、`768px`、`1440px` 以及 reduced-motion 模式检查标题换行、Hero 安全区、图片焦点、轮播控制和长英文/俄文文案。

### 9.2 新界面提交前检查

- 普通卡片是否避免了静态阴影和过大圆角？
- Hover 是否只在鼠标设备上增强，并且不会用灰色底板覆盖内容？

- 是否在 `375px`、`768px`、`1440px` 和 reduced-motion 下检查过？
- 是否避免使用其他品牌的素材、文案、Logo 或专属图形？

## 10. 当前允许例外

- Hero 标题可达到 `48px`；其他模块标题遵守 `28–32px`。
- 大型轮播控制面板可以使用 `16px` 圆角和半透明模糊背景。
- 弹窗、下拉菜单、侧栏可用轻投影，以区别于普通页面卡片。
- 管理后台允许使用基础 UI 库的紧凑控件和信息密度，不改变公开官网的视觉风格。
